# AGENTS.md — brief for an independent reviewer

This file exists for a second agent (or a human) reviewing OpsPilot. It points
at the places where a defect would matter most, and states what is already
asserted so review effort goes somewhere useful.

## Review these first

1. **The leakage boundary.**
   `backend/app/services/orders.py` must never join `order_outcomes`.
   `backend/app/services/analytics.py` is the only module that may, and only
   under `order_delivered_customer_date < snapshot_at`. Changing that `<` to
   `<=` would admit same-day deliveries an operator could not yet have seen.
   Asserted in `test_data_and_leakage.py`, `test_api.py`, `journey.spec.ts`.

2. **The approval boundary.**
   `backend/app/services/proposals.py`. A ticket may be created only there,
   only from `/proposals/{id}/approve`, and only for the owning session.
   `tickets.proposal_id` is `UNIQUE` — that constraint is what makes
   double-clicks and concurrent retries safe. Asserted in
   `test_approval_security.py`, including a real two-thread race.

3. **The verification gate.**
   `backend/app/agent/graph.py::verify`. It may only *reduce* what a report
   claims: drop facts citing unknown evidence ids, flag invented policy
   sections, downgrade a recommendation the policy forbids. If a change lets it
   *add* anything, that is a defect.

4. **Feature availability.**
   `data_pipeline/features.py::FEATURE_AVAILABILITY`. Every model feature needs
   an entry; the builder raises without one. The two history features are the
   subtle ones — they read prior outcomes, and are legal only because they read
   outcomes strictly earlier than each order's own handover.

## Claims that should be checked rather than trusted

- `docs/model_report.md` numbers are generated by `ml_pipeline/train.py`.
  Re-run it; the file is rewritten from measurements.
- `docs/data_audit.md` likewise, from `data_pipeline/audit.py`.
- The benchmark pass rate excludes skipped cases. Confirm that a skipped case
  is never counted as a pass (`run_benchmark.py::aggregate`).

## Known unverified

- `docker-compose.yml` has never been run: Docker cannot be installed on the
  development machine. `backend/Dockerfile` is exercised by Render's build.

## Working rules

- Do not weaken a test to make it pass. Every test here encodes a rule from
  the project plan.
- Do not add a feature without an availability justification.
- Do not commit a credential. CI scans for real key shapes and for remote
  database URLs; the local `opspilot_dev_pw@127.0.0.1` is documented setup and
  is deliberately allowed.
